المِرْتَال — al-Mirtāl

The Instrument of Tarteel

A Qur'an navigation instrument built around a formal computational system of recitational navigation:

رَتْلًا وَتَرْتِيلًا

Live instrument:

https://mirtal.vercel.app/

Repository:

---

1. What This Project Is

المِرْتَال (al-Mirtāl) is not a conventional Qur'an reader and is not designed merely to turn pages or display passages.

It is a computational navigation instrument for exploring coordinate-addressable relationships within the Qur'anic text.

The fixed text is the substrate.

The navigation field is computationally generated.

A رَتْلَة is a traversable sequence through that field.

The system therefore treats Qur'anic navigation as an addressable, reproducible and computationally inspectable process rather than as an ordinary linear reading interface.

---

2. The Governing Constraint

«ما نَفِدَتْ كَلِمَاتُ اللَّه»

Nothing stands between one رتلة and the next but the text itself.

Citations, coordinates, role labels, weights and computational metadata belong to the apparatus surrounding the text. They do not replace the text.

The system is designed so that generated navigation remains traceable to explicit Qur'anic coordinates.

No generated رتلة is intended to become an uncitable abstraction.

The fundamental constraint is:

Text first.
Coordinates second.
Traversal third.
Interpretation remains distinguishable from computation.

---

3. The Three Layers

The system deliberately distinguishes three layers.

Layer 0 — The Canonical Substrate

The Qur'anic text represented as addressable segments.

Coordinates may identify:

- sūrah
- āyah
- word
- word span
- other defined textual units

The substrate is not generated by the navigation engine.

---

Layer 1 — The Computational Field

The system derives navigational relationships from the addressable corpus.

This includes:

- candidate edges
- سبب generators
- coordinate relationships
- operators
- weights
- field construction
- traversal constraints
- Furqān generation
- رتلة generation

These are computational objects and should remain distinguishable from the Qur'anic text itself.

---

Layer 2 — The Traversal

A رتلة is an actual traversal through the computational field.

A traversal records where it began, what coordinates it visited, what operations produced its transitions, and the resulting sequence.

The same textual substrate may therefore support multiple valid computational traversals without altering the underlying text.

---

4. What Makes al-Mirtāl Different

A conventional Qur'an application asks:

«Where is the passage?»

al-Mirtāl additionally asks:

«From this coordinate, what addressable textual paths can be traversed?»

The interface therefore operates simultaneously as:

- reader
- coordinate system
- navigation instrument
- traversal engine
- computational field explorer
- machine-readable interface

The objective is not to replace ordinary reading.

The objective is to make another class of textual navigation computationally explicit.

---

5. Coordinate Addressing

The instrument exposes Qur'anic locations as machine-readable coordinates.

Examples include:

#30:4:5
#68:1
#68

These may represent, depending on the addressing mode:

- an āyah
- an āyah and word
- an entire sūrah
- other supported coordinate forms

Coordinates are therefore not merely visual labels.

They are addresses.

---

6. Programmatic Interface

The deployed instrument exposes a browser-level API through:

window.mirtal

Core operations include:

mirtal.lock(sura, aya, word?)
mirtal.walk(sura, aya, word?, depth?)
mirtal.field(sura, aya, word?)
mirtal.state()
mirtal.text(sura, aya)
mirtal.goto(hash)

These operations allow an external agent or application layer to:

- establish an anchor
- request a traversal
- inspect candidate field edges
- inspect live state
- retrieve textual material
- navigate directly to an address

The interface is therefore intended to be both human-drivable and machine-drivable.

---

7. The ن Lock

The ن surface represents a deeper capability layer of the instrument.

It is deliberately gated.

The interface exposes:

mirtal.nun.unlock('ن')
mirtal.nun.scopes()
mirtal.nun.grant(id)
mirtal.nun.revoke(id)
mirtal.nun.revokeAll()
mirtal.nun.granted(id)
mirtal.nun.dossier()

The lock is not merely decorative.

Its purpose is to make capability boundaries explicit.

Different scopes determine what the instrument is permitted to expose or perform, including traversal depth, cross-sūrah movement and access to raw scored field relationships.

8. Architecture

The repository is organized around a layered computational pipeline.

corpus.py
    Layer 0
    Segment-addressable Qur'anic corpus

sabab.py
    Layer 1
    سبب generators

ops.py
    Layer 2
    Operator algebra over citation sequences

generate.py
    Layers 3–4
    Furqān planning and رتلة planning

bundle.py
    Builds the embedded computational data bundle

app.html
    Main al-Mirtāl navigator

onboard.html
    Onboarding and architectural presentation

doc.html
    Formal description of the system

edges.json
    Generated candidate relationships

words.json
    Addressable word data

bundle.json
    Embedded/generated data representation

9. Build

The current build pipeline includes:

python3 bundle.py

followed by:

python3 build.py

The generated application artifacts include the navigator and associated built representations.

The repository intentionally keeps the computational generation pipeline separate from the presentation layer.

---

10. Reproducibility

A central design principle is that a generated traversal should be inspectable.

A رتلة should not exist merely because a model or human says that it exists.

Where supported, the system should be able to expose:

- originating coordinate
- destination coordinate
- textual basis
- operation used
- traversal depth
- field relationship
- score or weight
- resulting sequence

This allows a traversal to be examined independently of the prose used to describe it.

---

11. Computational Claims vs. Interpretive Claims

This distinction is fundamental to the project.

The software may computationally establish that:

- two coordinates exist
- a relationship was generated
- an edge satisfies a defined rule
- a traversal follows a defined operator
- a score was calculated
- a path is reproducible

Those are computational claims.

A statement about what that relationship means is a separate interpretive claim.

al-Mirtāl is designed to preserve that distinction.

The instrument should expose the evidence and traversal mechanics rather than silently converting computational proximity into asserted interpretation.

---

12. Design Principle

The central principle can be stated as:

The Qur'an remains fixed.
The field of apprehension may be navigated.
The traversal is recorded.
The coordinates remain recoverable.

The instrument does not alter the underlying text.

It constructs an addressable computational environment around it.

15. Project Status

al-Mirtāl is an evolving research and software project.

The system should be understood as a computational instrument under active development rather than as a finished scholarly authority.

New traversal operators, field generators, addressing schemes, validation procedures and interface capabilities may be added over time.

When new mechanisms are introduced, they should remain distinguishable from:

1. the canonical textual substrate;
2. the computational rule that produced a result; and
3. the human interpretation of that result.

16. Core Principle

The purpose of al-Mirtāl is not to manufacture meanings.

It is to make textual navigation visible, addressable, traversable and inspectable.

The fundamental object is therefore not merely the page.

It is the path.
